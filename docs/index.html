Shopify apps on Firebase, in one command.

Nitrogen scaffolds a Shopify app, deploys it to Firebase, and hands you an install link. No framework to learn and no server to keep running.

$npx @mksd0398/nitrogen my-app
Read the quick start View on GitHub

Needs Node.js 20 or newer, a Shopify Partner account, and a Firebase project on the Blaze plan.

What the command does

You answer a few questions. It does the rest, in this order, and stops to tell you if something needs your attention.

  1. Signs you in to Shopify and creates the appYour client id and secret are read from the Shopify CLI. You never paste them.
  2. Creates and provisions the Firebase projectFirestore, Hosting and Functions, in the region you choose.
  3. Stores the client secret in Secret ManagerIt never sits in a file that ships with your code.
  4. Deploys, then registers the live URLs with ShopifyWhen it finishes, the app is installable.

What you get

A working app you can read end to end, in TypeScript or JavaScript.

One function per API resource

Each scales, times out and deploys on its own, so a slow import cannot starve the routes merchants are waiting on.

Verification that fails closed

Webhooks, session tokens, the App Proxy and OAuth all refuse a request when a signature is missing, not only when it is wrong.

Single- or multi-tenant

Lock the app to one store, open it to many, or run several Shopify apps on one backend. The tenant always comes from a verified signature.

Installs the way Shopify installs

Works from the App Store or the admin with no install link, using token exchange. Uninstall and reinstall are handled.

API keys for outside callers

Let a mobile app or a script call your API. Keys are hashed at rest, scoped, and owned by one store.

Rate limits and a spending cap

A per-caller request limit, Shopify's own throttling passed through, and a ceiling on instances.

A reference inside your app

All 50 Polaris web components and all 26 App Bridge APIs, each with a working example to copy.

Tests included

Every project ships with a test suite that needs no emulator or network. It also checks your routes match your deploy config.

No build step on the frontend

Plain HTML with Polaris web components and App Bridge. No React, no bundler.

Writing an API

A route is one entry in a table. Authentication, rate limiting, routing and errors are handled before your code runs.

// functions/src/api/orders.ts
export default endpoint({
  "GET /api/orders": async (ctx) => {
    const data = await graphql(ctx,
      `{ orders(first: 10) { nodes { id name } } }`);
    return { orders: data.orders.nodes };
  },

  "GET /api/orders/:id": async (ctx) => {
    // ctx.shop comes from the verified token,
    // never from the request
    return { id: ctx.params.id, shop: ctx.shop };
  },
});

// functions/src/index.ts
export const orders = onRequest(base, ordersApi);
  • Return the JSON to send, or throw an HttpError. Anything else becomes a 500 whose detail stays in the logs.
  • index is the whole API surface. If a function is not exported there, it does not exist.
  • Open a route to API keys with { apiKey: "read" }, or to the storefront with { auth: "proxy" }.
  • npm test fails if an export and its rewrite in firebase.json disagree, before you deploy.

What it costs

Everything scales to zero, so an app nobody is using costs nothing. Firebase's Blaze plan is pay-as-you-go with a free tier, and needs a billing account.

$0while the app is idle
~1,200daily active stores inside the free tier
~$32a month at 10,000 daily active stores

Estimates, assuming 10 API calls per store per day at 0.5 seconds each, at Google's US list prices. Function compute is what runs out first. The README shows the arithmetic so you can redo it with your own numbers.
